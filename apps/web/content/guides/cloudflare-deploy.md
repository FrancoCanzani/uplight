# Deploy Uplight to Cloudflare Workers

Get your own uptime monitoring infrastructure running globally in minutes. Cloudflare Workers' free tier is generous enough for most use cases.

## Why Cloudflare Workers?

### Global by Default

- **300+ edge locations** worldwide
- **Sub-50ms latency** from anywhere
- **No cold starts** like traditional serverless

### Free Tier is Generous

- **100,000 requests/day** free
- **10ms CPU time** per request
- **Workers KV storage** included
- **D1 database** included

For most monitoring needs, you'll never pay.

### Reliability

Cloudflare's network is one of the most reliable on the planet. Your monitoring infrastructure runs on the same network that powers 20% of the web.

## Prerequisites

Before starting, you'll need:

- **Cloudflare account** (free at [cloudflare.com](https://cloudflare.com))
- **Node.js 18+** installed
- **Bun** or npm (Bun recommended)
- **5 minutes** of your time

## Method 1: One-Click Deploy

The fastest way to get started:

[![Deploy to Cloudflare Workers](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/francocanzani/uplight)

1. Click the button above
2. Authorize Cloudflare to access GitHub
3. Follow the prompts
4. Done!

Your Uplight instance will be live at `uplight.<your-subdomain>.workers.dev`

## Method 2: CLI Deployment

For more control, use the CLI:

### Step 1: Create Project

```bash
npx create-uplight@latest
```

Or with Bun:
```bash
bunx create-uplight@latest
```

Follow the prompts:
- Project name: `my-uplight`
- Deploy target: Cloudflare Workers

### Step 2: Configure

Navigate to your project:
```bash
cd my-uplight
```

Edit `wrangler.toml` if needed:
```toml
name = "uplight"
main = "src/index.ts"
compatibility_date = "2024-01-01"

[vars]
ENVIRONMENT = "production"

[[d1_databases]]
binding = "DB"
database_name = "uplight"
database_id = "<auto-generated>"

[[kv_namespaces]]
binding = "KV"
id = "<auto-generated>"
```

### Step 3: Deploy

```bash
# Login to Cloudflare (if not already)
npx wrangler login

# Deploy
bun run deploy
# or: npm run deploy
```

Done! Note your worker URL.

## Method 3: Fork and Deploy

For maximum customization:

### Step 1: Fork Repository

1. Go to [github.com/francocanzani/uplight](https://github.com/francocanzani/uplight)
2. Click **Fork**
3. Clone your fork locally

### Step 2: Install Dependencies

```bash
cd uplight
bun install
```

### Step 3: Configure Cloudflare

Create D1 database:
```bash
npx wrangler d1 create uplight-db
```

Copy the database ID and update `wrangler.toml`.

Create KV namespace:
```bash
npx wrangler kv:namespace create UPLIGHT_KV
```

Update `wrangler.toml` with the namespace ID.

### Step 4: Deploy

```bash
bun run deploy
```

## Post-Deployment Setup

### Access Your Instance

Your Uplight instance is now live at:
```
https://uplight.<your-subdomain>.workers.dev
```

### Create Admin Account

1. Visit your instance URL
2. Click "Sign Up"
3. Create your account
4. You're the first user = admin

### Add Custom Domain (Optional)

1. Go to Cloudflare Dashboard
2. Select your worker
3. Go to **Triggers** → **Custom Domains**
4. Add your domain: `uptime.yourdomain.com`

Cloudflare handles SSL automatically.

## Configuration Options

### Environment Variables

Set in Cloudflare Dashboard or `wrangler.toml`:

| Variable | Description | Default |
|----------|-------------|---------|
| `ENVIRONMENT` | production/development | development |
| `AUTH_SECRET` | Session encryption key | auto-generated |
| `GITHUB_CLIENT_ID` | GitHub OAuth (optional) | - |
| `GITHUB_CLIENT_SECRET` | GitHub OAuth (optional) | - |

### Database

Uplight uses Cloudflare D1 (SQLite at the edge):

```bash
# View database
npx wrangler d1 execute uplight-db --command "SELECT * FROM monitor LIMIT 5"

# Run migrations
npx wrangler d1 migrations apply uplight-db
```

### Cron Triggers

Monitoring checks run on schedules. Configure in `wrangler.toml`:

```toml
[triggers]
crons = ["* * * * *"]  # Every minute
```

## Monitoring Architecture

Understanding how it works:

```
┌─────────────────────────────────────────────────────┐
│                  Cloudflare Workers                  │
├─────────────────────────────────────────────────────┤

│  ┌──────────┐    ┌──────────┐    ┌──────────┐     │
│  │ Worker 1 │    │ Worker 2 │    │ Worker N │     │
│  │  (wnam)  │    │  (weur)  │    │  (apac)  │     │
│  └────┬─────┘    └────┬─────┘    └────┬─────┘     │
│       │               │               │           │
│       └───────────────┴───────────────┘           │
│                       │                           │
│              ┌────────┴────────┐                  │
│              │   Cloudflare    │                  │

│                                                   │
└─────────────────────────────────────────────────────┘
```

Workers at the edge perform checks and write results to D1.

## Cost Breakdown

### Cloudflare Free Tier

| Resource | Free Allowance | Uplight Usage |
|----------|----------------|---------------|
| Worker requests | 100k/day | ~1,440/day (1 monitor, 1 region) |
| CPU time | 10ms/request | ~5ms average |
| D1 reads | 5M/day | Minimal |
| D1 writes | 100k/day | ~1,440/day per monitor |
| KV reads | 100k/day | Minimal |
| KV writes | 1k/day | Minimal |

**Translation**: Free tier supports ~50-70 monitors with 1-minute intervals across multiple regions.

### When You Might Pay

- 100+ monitors with 1-minute intervals
- Many regions per monitor
- Heavy dashboard usage

Paid plans start at $5/month and remove most limits.

## Scaling Considerations

### Database Size

D1 handles millions of rows easily. Consider:
- Data retention policy (delete checks older than 90 days)
- Index optimization for queries
- Batch inserts for efficiency

### Request Volume

High monitor counts = more cron executions:
- 100 monitors × 1 min interval = 6,000 checks/hour
- × 9 regions = 54,000 checks/hour

Still well within free tier if optimized.

## Troubleshooting

### Deployment Fails

```bash
# Check wrangler version
npx wrangler --version

# Update if needed
npm update wrangler -g

# Verify login
npx wrangler whoami
```

### Database Issues

```bash
# Check database exists
npx wrangler d1 list

# Run migrations manually
npx wrangler d1 migrations apply uplight-db --local

# Debug locally
npx wrangler dev
```

### Cron Not Running

1. Check `wrangler.toml` cron configuration
2. View logs in Cloudflare Dashboard
3. Verify worker is deployed

### Custom Domain SSL

If custom domain shows SSL errors:
1. Verify CNAME record is correct
2. Wait for propagation (up to 24 hours)
3. Check Cloudflare SSL settings

## Security Considerations

### Authentication

- Enable proper auth (GitHub OAuth recommended)
- Use strong AUTH_SECRET
- Don't expose admin routes

### Data

- Monitor data stays in your Cloudflare account
- D1 data is encrypted at rest
- Workers run in isolated environments

### Network

- All traffic is HTTPS
- Cloudflare handles DDoS protection
- Rate limiting built into Workers
